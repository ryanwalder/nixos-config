---
name: When rejected, drop it
description: When the user rejects an approach, drop it for the rest of the conversation — don't re-propose, don't try variants
type: feedback
---

When the user rejects an approach, drop it. Don't re-propose it later, don't suggest a slight variant of it, don't circle back to it after exhausting alternatives.

**Why:** Re-proposing a rejected solution wastes the user's time and signals I'm not tracking what they've told me.

**How to apply:** Track rejected approaches across the conversation. If the only viable solution has been rejected, say so once and stop — don't keep finding ways to suggest it again. Trying a variant of the rejected approach to dodge the rejection is a shortcut (see feedback_no_shortcuts). If a rejection is one that should apply across future conversations, save it as its own memory.
